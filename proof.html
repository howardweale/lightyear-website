What we proved, and on whose system

An eight-service core banking application, Oracle to PostgreSQL, on GCP

CloudBank is Oracle's own core banking reference application. We took it end to end: schema, stored logic, messaging, identity and deployment — every step held to the same standard of evidence, with an autonomous factory doing the work and a deterministic gate deciding whether it counted.

Data and logic

Schema projection with type and scale fidelity, stored logic qualified as bounded supporting evidence rather than an unqualified claim.

Messaging

Oracle AQ replaced by a PostgreSQL durable work queue — row locks with SKIP LOCKED, at-least-once with idempotent keys, FIFO within an aggregate, governed dead-letter replay.

Identity

OAuth2/OIDC with client-credentials service identity and the JWT subject preserved through to account authorization. No static shared headers.

Platform

Kubernetes on GKE with immutable sha256 digest image policy, Cloud SQL PostgreSQL 16, and a cutover rehearsal contract that makes rollback mandatory and observed rather than documented.

Both lanes run in Google Cloud. The Verdict Engine sits between them, and neither can write to the other.

Every item above is backed by evidence you can inspect. No claim here stands on our word alone.

How the work gets done

We build the factory. We also build what stops it.

We run an autonomous factory. It generates database transformations, it runs unattended, and it is gated by an engine that has refused its own output. That is how we know what a generator gets wrong — we watch ours get it wrong every week.

We do not sell the factory. We sell what stops it. Three agents propose. One deterministic judge, which never sees the expected values, decides whether the result counted. A person approves anything the judge is not permitted to.

Failure routes back carrying which field diverged, never the value it should have had.
