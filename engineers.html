Work orders

A work order is a contract, not a prompt.

It declares the paths an agent may touch, the slice of the graph it may read, the gates that must pass and the timeouts. An agent can’t widen its scope at run time. expose_output_to_builder defaults to false and must be a real JSON boolean.

{
  "id": "intcalc-repair",
  "allowed_paths": ["src/interest/**"],
  "graph_scope": ["CBACT04C", "TCATBAL"],
  "gates": [
    { "id": "unit",    "expose_output_to_builder": true  },
    { "id": "holdout", "expose_output_to_builder": false }
  ]
}

Accepted differences

Some differences are meaningless: a run timestamp, a padding convention. Each one is a controlled entry with a written reason, a named owner and a review date. The validator fails closed.

lightyr validate-normalizations --ledger spec/normalizations.json

# NORMALIZATION_REVIEW_EXPIRED:fixed-width-padding:2026-02-22
# NORMALIZATION_GOVERNANCE_MISSING:decimal-canonical:owner

CI integration

Exit codes route directly. Treat 2 as a pipeline error rather than a test failure: the run proved nothing. The second step asserts a run is side-effect free.

- name: Differential verification
  run: |
    lightyr compare --expected ref/ --actual out/ --report r.json
    # 0 faithful · 1 divergent · 2 indeterminate

- name: Reject runs that mutate tracked evidence
  run: git diff --exit-code

Coverage that finds the risk

We measure arc coverage, not statement coverage. A corpus can execute every line of a validation paragraph and never take the reject branch, and reject branches are where defects survive to go-live. Where the corpus misses one, we generate the input and run it through the legacy system first.
